## 0. 结论先行

### 0.1 一句话诊断

Albumiv 像一间设备齐全、作品过硬的暗房，但墙上同时挂着四套不同的开关面板。

用户每进入一个新页面，都要重新学习一次"这里怎么点"：同样是"切换"，相册是 32dp 的滑块，清理页是 48dp 的分段控件，编辑器是 68dp 的底部 Tab，底栏是只给选中项显示文字的图标。这不是审美品味问题，而是**缺少一个对设计系统负责的人**。

### 0.2 七个数字

| 指标 | 实测 | 说明 |
| --- | --- | --- |
| 字号 | **17 级**（9–28sp） | 同一语义的标题/正文/说明在不同页面用不同字号 |
| 圆角 | **15 种**裸写值 | 最常用的 7/5/10dp 恰好都不在设计 Token 里 |
| 页面顶栏 | **4 种高度 + 1 条 36dp 副栏** | 44 / 60 / 64 / 68dp，外加选择模式 36dp |
| 默认蓝正文 | **3.11:1** | WCAG AA 正文要求 4.5:1；主按钮白字同样 3.11:1 |
| 设置卡片/背景 | **1.02:1** | 卡片几乎不可见；深色主题卡片/背景 1.11:1 |
| 反馈通道 | **81 处 Toast : 0 处 Snackbar** | 结果不可操作、不可撤销、不可回看 |
| 动效 | **16 种时长、4 条近似曲线、0 个 spring** | 全部 `tween`，没有可直接拖拽的物理感 |

另外两个不在表里、但同样关键的数字：**27 处 30–43dp 的尺寸声明，其中多处在可点容器上**；**109 个源文件里只有 19 个出现显式 `contentDescription`**。

### 0.3 已经做得好的，不要动

在批评之前必须先确认资产。以下判断是对的，重构时应作为约束保留：

1. **内容优先。** 网格几乎无装饰，缩略图铺满，查看器用纯黑画布，编辑器把图像放在绝对中心。这是相册类产品最难得的分寸。
2. **按压缩放。** 相册封面 0.975、媒体缩略图 0.965 的 85–90ms 回弹，是全局最有效的"手感"来源（[`MediaTiles.kt`](../app/src/main/java/com/example/album/ui/components/MediaTiles.kt#L88-L101)、[`MediaTiles.kt`](../app/src/main/java/com/example/album/ui/components/MediaTiles.kt#L196-L210)）。
3. **共享元素转场。** 图片从网格飞入查看器，是当前最有"成品感"的一处动效（[`SharedMediaTransition.kt`](../app/src/main/java/com/example/album/ui/components/SharedMediaTransition.kt)）。
4. **本地优先的克制。** 无广告、无社交、无云端入口；设置项虽然多，但都围绕本地媒体。
5. **库页空态有完整叙事。** 无权限、无内容、无搜索结果、扫描失败四种状态分开处理，并给出动作（[`LibraryEmptyState.kt`](../app/src/main/java/com/example/album/ui/screens/LibraryEmptyState.kt#L47-L114)）。
6. **手势提示页。** 承认"很多能力藏在长按和双指里"，并集中说明，这是诚实的产品态度。

### 0.4 如果两周只做六件事

| 顺序 | 动作 | 直接收益 |
| --- | --- | --- |
| 1 | 建立**可访问色板**：强调色分出"填充/正文/深色正文"三种值，修掉默认蓝 3.11:1、金色 1.49:1 | 一眼可读，7 套主题色都成立 |
| 2 | 修**深色模式系统栏与启动白闪**：`values-night` + 动态 `isAppearanceLightStatusBars` | 深色模式不再是半成品 |
| 3 | 统一**页面骨架**：56dp 顶栏 + 可折叠筛选行 + 全标签底栏 | 用户知道"我在哪、能去哪" |
| 4 | 选择模式只留**一套操作面**，删除 36dp 副条 | 多选不再两排按钮打架 |
| 5 | 用 **Snackbar + 撤销**替换大部分 Toast，破坏性操作分三级 | 结果可回看、可挽回 |
| 6 | 把 **Token 真正用起来**：6 级字号、5 种圆角、4 种间距、3 种时长 | 后续每个页面自动一致 |

### 0.5 评分

| 维度 | 分数 | 理由 |
| --- | --- | --- |
| 内容优先 | **8.5 / 10** | 网格、查看器、编辑器都把图像放在第一位 |
| 视觉一致性 | **5.0 / 10** | 四套 Tab、四套按钮、15 种圆角、5 种顶栏 |
| 信息层级 | **6.0 / 10** | 页面标题缺位、裸数字、卡片无边界 |
| 交互一致性 | **5.0 / 10** | 选择模式两套操作、两种搜索框、Toast 单一通道 |
| 动效完成度 | **6.5 / 10** | 有共享元素与按压缩放，但全 tween、无编排、顶栏与内容不同步 |
| 可访问性 | **4.0 / 10** | 对比度、触控、语义、字体缩放四项均有硬伤 |
| 品牌辨识 | **5.0 / 10** | 系统默认字 + Pixiv 蓝 + 图标里的第三种绿 |
| 工程克制 | **7.0 / 10** | 自建组件、注释详尽；但有死代码、硬编码与原型遗留命名 |

**综合约 5.8 / 10。** 这是一个"再往前一步就会很像样"的位置：不需要推翻重做，需要一次系统性的收口。

## 1. 审阅范围与方法

### 1.1 做了什么

- **逐屏走查**：相册根页、时间轴、视频播放器、编辑器、文件清理、壁纸队列、幻灯片队列、Pixiv 归档、设置、空态与提示弹层。
- **代码反推**：从 `ui/theme/`、`ui/components/`、`ui/screens/` 读取实际尺寸、颜色、动效与语义，而不是只看截图。
- **量化**：对 109 个 Kotlin 文件做颜色字面量、字号、圆角、`tween`/`spring`、`Toast`/`Snackbar`、`contentDescription` 的全量统计。
- **对比度**：按 WCAG 2.1 相对亮度公式计算关键前景/背景组合。
- **平台对照**：Android Material 3、Android 无障碍指南、WCAG 2.2 AA、Google Photos 等同类产品的交互惯性。

### 1.2 没做什么

- **没有真机 TalkBack 逐项走查**、没有在 1.3/1.5/2.0 字体缩放下逐屏截图。相关结论会标注"需真机验证"，并列入第 7 章验收脚本。
- **没有做性能 profile**。本文的动效建议以"不增加掉帧风险"为前提，具体帧率需按现有 benchmark 复测。
- **没有评价内容本身**。截图中的媒体内容是用户素材，本文只讨论界面结构。

### 1.3 评价标准

一条设计决策是否成立，只看四件事：

1. **可预期**：下一步会发生什么，用户是否不用猜？
2. **可区分**：两个不同层级/状态，看起来是否真的不同？
3. **可到达**：手指、屏幕阅读器、大字体用户是否都能完成？
4. **可维护**：新页面能否只靠 Token 和组件拼出来，而不是再写一套？

## 2. 定位：私人暗房，而不是社交相册

### 2.1 气质定位

Albumiv 的差异不是"更漂亮的相册"，而是**本地、可归档、可编辑、可展示的私人暗房**。这决定了视觉气质应该是：

| 要 | 不要 |
| --- | --- |
| 安静的中性色，让作品发声 | 糖果色渐变、玻璃拟态、彩色阴影 |
| 精确的网格与细线，像接触印样（contact sheet） | 大圆角卡片堆叠、漂浮的胶囊 |
| 少量"安全灯"式的强调色，只标记状态 | 强调色铺满图标、箭头、数字 |
| 系统字体 + 等宽数字，信息密度高 | 每页换一种展示字体 |
| 动效像机械快门：短、准、可中断 | 长而软的入场、无意义的循环动画 |

一句话：**界面应该像暗房的白墙和夹具，而不是另一件作品。**

### 2.2 五条设计原则

这五条不是口号，每条都配一个可验收的判据。

**P1 内容唯一主角。**
任一屏幕的饱和色不超过 1 处（当前状态色），非内容色不超过 3 种。
> 判据：把截图转成灰度，仍能一眼看出"哪里是图片、哪里是控件"。

**P2 一个动作，一种长相。**
同一语义在全 App 使用同一尺寸、形状、文案位置。
> 判据：把"切换 / 主要按钮 / 危险按钮 / 搜索框"四类控件截图并排，必须像同一个设计师做的。

**P3 状态可见，结果可逆。**
每个破坏性操作，要么事前说明后果，要么事后提供撤销；二者至少其一。
> 判据：用户误删一张图，能否在 5 秒内、不离开当前页地恢复？

**P4 手势是加速器，不是入口。**
所有手势都必须有一个可见的等价入口。
> 判据：一个从没用过 App 的人，不打开"使用提示"，能否完成删除、收藏、加入壁纸队列？

**P5 先可达，再精致。**
正文 4.5:1、触控 48dp、字体放大 2.0 倍不截断、状态不只靠颜色。
> 判据：见第 7 章验收脚本。

### 2.3 平台选择：Android 的行为，自己的皮肤

当前界面是"Material 骨架 + iOS 皮肤"：24/28dp 大圆角弹层、80% 宽、2dp 描边胶囊、17sp 按钮，这些是 iOS 的动作；但底栏、返回、溢出菜单又是 Android 的。结果是两边用户都觉得"差一点"。

**建议明确站队：交互遵循 Android，视觉保留自己的编辑感。**

- 遵循 Android 的部分：系统返回/预测性返回、底栏全标签、上下文操作栏、Snackbar、分享面板、48dp 触控、系统字体缩放。
- 保留自己皮肤的部分：中性纸色、细线分隔、胶囊主按钮、暗房式纯黑查看器、7 套强调色。
- 放弃的部分：iOS 式"描边胶囊 + 17sp + 28dp 全圆角"的弹层语言；它不是品牌，是原型的残留。

这样既不会让 Android 用户觉得"这是台假 iPhone"，也不会丢掉已经建立的安静气质。

## 3. 诊断：七个"不统一"

> 本章只描述现象与证据，具体改法在第 4–8 章。问题编号用于路线图索引。

### 3.1 颜色：变量名在说谎，强调色没有层级

#### C-01 变量名与实际色相错位

[`Color.kt`](../app/src/main/java/com/example/album/ui/theme/Color.kt#L6-L11) 的定义：

| 变量名 | 实际色值 | 实际颜色 | 问题 |
| --- | --- | --- | --- |
| `VaultGreen` | `#FA007D` | 玫红 | 名字与色相相反 |
| `VaultBlue` | `#0096FA` | 蓝 | 正确 |
| `VaultTeal` | `#4B00FA` | 靛紫 | 名字与色相相反 |
| `VaultOrange` | `#FA7D00` | 橙 | 正确 |
| `VaultCoral` | `#FAD000` | 金 | 名字与色相不符 |
| `VaultViolet` | `#9200FA` | 紫 | 正确 |
| `VaultForest` | `#1E8E3E` | 绿 | 正确 |

这不是"改个名"的小事：当设计稿写"用 VaultGreen"，工程拿到的是玫红；当新人读代码，他学到的色彩语义是错的。**设计系统的第一份文档就是变量名。**

**改法**：按色相重命名为 `AccentMagenta / AccentBlue / AccentIndigo / AccentOrange / AccentGold / AccentViolet / AccentForest`，`ThemeAccent` 的显示名也从"Pixiv 蓝"改回"蓝"（"Pixiv 蓝"把品牌名借给了颜色，反而限制了它）。

#### C-02 七个强调色，没有"色调层级"

当前每个强调色只有一个值，被同时用于：填充按钮、12sp 正文、图标 tint、chevron、选中底色、进度条。一个值不可能同时满足这些场景的对比度与视觉重量。

`Color.kt` 里其实已经写了 [`lightAccentForText()`](../app/src/main/java/com/example/album/ui/theme/Color.kt#L56-L69)——按亮度逐步压暗，直到白字达标。**这个函数从未被调用。** 它说明作者意识到了问题，但没有把"色板"做完。

**改法**：每个强调色拆成 5 个角色（见 [8.2](#82-颜色角色与色板)）：`hue`（色相展示）、`fill`（实心填充）、`onFill`（填充上的文字）、`textLight` / `textDark`（正文/图标），外加 12–14% 的 `container`。

#### C-03 对比度：默认主题的正文与按钮都不达标

实算结果（WCAG 2.1）：

| 组合 | 比值 | 正文 AA (4.5) | 大字/UI AA (3.0) |
| --- | --- | --- | --- |
| 默认蓝 `#0096FA` / 白 | **3.11:1** | 失败 | 通过（勉强） |
| 白 / 默认蓝（主按钮） | **3.11:1** | 失败 | 通过（勉强） |
| 金 `#FAD000` / 白 | **1.49:1** | 失败 | 失败 |
| 橙 `#FA7D00` / 白 | **2.63:1** | 失败 | 失败 |
| 玫红 `#FA007D` / 白 | **3.92:1** | 失败 | 通过 |
| 森林绿 `#1E8E3E` / 白 | **4.21:1** | 失败 | 通过 |
| 紫 `#9200FA` / 白 | 5.83:1 | 通过 | 通过 |
| 靛蓝 `#4B00FA` / 白 | 7.84:1 | 通过 | 通过 |
| 次要文字 `#777B79` / 白 | **4.29:1** | 失败 | 通过 |
| 星标 `#FFD60A` / 白 | **1.41:1** | 失败 | 失败 |
| 星标 `#FFC107` / 白 | **1.63:1** | 失败 | 失败 |
| 危险 `#D32F2F` / 白 | 4.98:1 | 通过 | 通过 |
| iOS 红 `#FF453A` / 白 | **3.41:1** | 失败 | 通过 |
| 深色靛蓝 / `#121715` | **2.31:1** | 失败 | 失败 |
| 深色紫 / `#121715` | **3.11:1** | 失败 | 失败 |
| 深色卡片 / 背景 | **1.11:1** | — | 边界不可见 |

**七个强调色里，浅色主题只有靛蓝、紫罗兰能直接当正文；深色主题靛蓝、紫罗兰反过来不达标。** 现在设置页的"值"文字、顶栏的"应用/播放"、清理页的"扫描/清理全部"都用强调色直接写，选金色主题时几乎不可读。

这不是"调一下就好"，而是必须建立**按主题自动选择色值**的规则。

#### C-04 三套红、一套 iOS 色板

| 用途 | 色值 | 出处 |
| --- | --- | --- |
| Material `error` | 默认 `#B3261E` | `MaterialTheme.colorScheme.error`（弹层危险按钮） |
| 固定红 | `#D32F2F` | 顶栏删除、查看器删除（[`VaultTopBar.kt`](../app/src/main/java/com/example/album/ui/components/VaultTopBar.kt#L250)、[`MediaViewer.kt`](../app/src/main/java/com/example/album/ui/components/MediaViewer.kt#L980)） |
| iOS 红 | `#FF453A` | 清理页"停止/清理全部"（[`CleanupScreen.kt`](../app/src/main/java/com/example/album/ui/screens/CleanupScreen.kt#L840-L849)） |
| iOS 红 | `#FF3B30` | 编辑器默认画笔色 |
| iOS 绿/蓝/紫/橙 | `#34C759` `#007AFF` `#AF52DE` `#FF9500` | 编辑器调色板 |

同一款 App 里"删除"有三种红，深色主题下还都不一定够亮。**危险色必须只有一个语义来源。**

#### C-05 星标：两种黄，且都在白底上消失

- 顶栏/查看器：`#FFD60A`（[`VaultTopBar.kt`](../app/src/main/java/com/example/album/ui/components/VaultTopBar.kt#L403-L406)、[`MediaViewer.kt`](../app/src/main/java/com/example/album/ui/components/MediaViewer.kt#L921)）
- 缩略图徽标：`#FFC107`（[`MediaTiles.kt`](../app/src/main/java/com/example/album/ui/components/MediaTiles.kt#L248-L256)）

黄色在白底只有 1.4–1.6:1。作为"收藏"这种必须一眼看到的状态，它只在深色图片上有效，在浅色图片或设置页上就消失了。

**改法**：收藏 = 实心星 + 1px 描边/深色底衬（保证任何底图上可见），颜色统一为 `#F2B300`（白底 3.0:1 以上）或直接用强调色；同时提供文字状态（详情页"已收藏"），不只靠颜色。

#### C-06 表面：卡片与背景只差 1.02

设置页卡片用 `surfaceVariant`（`#F4F5F4`）铺在背景（`#F7F7F7`）上，对比度 **1.02:1**。截图里卡片边界几乎看不见，用户只能靠 16dp 间距猜分组。深色主题同样只有 1.11:1。

**改法**：不要靠"更浅的灰"分层，靠 **1px 细线 + 明度差 + 留白**。细线不需要 3:1（分组还由标题和间距表达），但必须可见：`#E2E0DA` 对纸色约 1.2:1，对白约 1.3:1，足够形成"印样纸上的框"。真正的交互控件（开关关闭态、输入框）才需要 3:1 的边线。

### 3.2 字体：17 级字号，等于没有字阶

#### T-01 字号分布

全量统计（非零字号）：

| 字号 | 次数 | 典型用途 |
| --- | --- | --- |
| 9sp | 4 | 视频时长徽标、清理阶段标签 |
| 10sp | 11 | 相册数量、徽标 |
| 11sp | 20 | 底栏标签、说明 |
| 12sp | 23 | 行值、清理 Tab |
| 13sp | 35 | 正文、相册名、搜索 |
| 14sp | 25 | 顶栏动作、查看器标题 |
| 15sp | 11 | 弹层正文、设置值 |
| 16sp | 15 | 通用正文 |
| 17sp | 16 | 弹层标题、清理摘要 |
| 18sp | 6 | 少量标题 |
| 19sp | 3 | 弹层标题 |
| 20sp | 11 | 页面标题 |
| 21sp | 1 | 单处 |
| 22sp | 4 | 顶栏标题 |
| 24sp | 2 | 大标题 |
| 26sp | 1 | 单处 |
| 28sp | 2 | 品牌字 |

`VaultText` 只定义了 8 个角色（[`Type.kt`](../app/src/main/java/com/example/album/ui/theme/Type.kt#L42-L53)），但实际用了 17 级。更常见的是**绕过角色直接写**：`fontSize = 17.sp` 在清理页、弹层、编辑器各写一遍，行高还各不相同。

**9sp 是最危险的一档。** 在 3dp 间距的 4 列网格里，9sp 的视频时长几乎不可读；在清理阶段标签里，9sp 中文在 1.0 倍字体下已经吃力，2.0 倍时必然溢出。

**改法**：收成 6 级——28 / 20 / 17 / 15 / 13 / 11，外加 10 仅用于"徽标数字"且必须配 4.5:1 底色。所有 `fontSize` 字面量替换为 `VaultType.*`。

#### T-02 字重与行高没有配对规则

- 顶栏标题 22sp / 28 行高 / SemiBold；
- 弹层标题 17–19sp / 22–24 行高 / SemiBold；
- 清理摘要 17sp / Medium；
- 页面标题有时 20sp（`titleLarge`），有时 22sp（`VaultText.TopBarTitle`）。

结果是"标题"在不同页面视觉重量不同：Pixiv 页的 "Pixiv" 很重，清理页没有标题，设置子页的"界面"又轻。

**改法**：定义四级字重：Regular 400（正文）、Medium 500（标签/强调）、SemiBold 600（标题）、Bold 700（仅数字/角标）。标题只用 SemiBold，正文只用 400/500。

#### T-03 界面用系统字，编辑器却背了 60 MiB 字库

`res/font/` 里有 10 个 TTF，合计约 **60 MiB**：Noto Sans SC、Noto Serif SC、站酷系列、马善政、龙藏、刘建毛草等。它们**只服务于编辑器的文字工具**；主界面用 `FontFamily.Default`，即厂商系统字体。

这带来三个问题：

1. **品牌没有字体声音**：同一台小米、OPPO、三星上，Albumiv 的界面字完全不同。
2. **包体代价**：60 MiB 字库对一款本地相册是很重的固定成本。
3. **图标/文字语义错位**：`EditorFont.Monospace` 的标签是"毛笔楷书"，映射到马善政；`Cursive` 是"龙藏体"；`Wide` 是"毛草"。内部枚举名与真实字体不符，后续维护容易选错（[`ImageEditorEngine.kt`](../app/src/main/java/com/example/album/ui/editor/ImageEditorEngine.kt#L48-L53)）。

**改法**：
- 界面继续用系统字（CJK 场景这是正确选择），但显式设置 `fontFeatureSettings = "tnum"` 给所有数字，保证计数/时码等宽。
- 编辑器字库收敛到 4 款（黑体/宋体/楷体/一款手写），其余改为"可选下载"或移除；枚举按真实字体重命名。
- 若坚持内置，至少给每款字体标注真实名称与授权，避免"点阵体"实际是日文像素字体这类错配。

### 3.3 形状、间距、栅格：15 种圆角，5 套栅格节奏

#### S-01 圆角

裸写值统计：

| 圆角 | 次数 | 典型位置 |
| --- | --- | --- |
| 7dp | 16 | 大量卡片、行、Pixiv 入口 |
| 5dp | 11 | 编辑器输入框、小控件 |
| 10dp | 6 | 顶栏开关容器、图标底 |
| 8dp | 4 | 相册封面、清理 Tab |
| 6dp | 4 | 清理 Tab 选中态 |
| 28dp | 4 | 弹层 |
| 24dp | 3 | 弹层/播放徽标 |
| 20dp | 2 | 分辨率浮层 |
| 9/12/14/16/4/1/0 | 各 1–2 | 零散 |

`VaultShape` 定义的是 4/8/12/16/Full（[`Tokens.kt`](../app/src/main/java/com/example/album/ui/theme/Tokens.kt#L15-L21)），但**最常用的 7/5/10 都不在 Token 里**。这不是"迁移没做完"，而是设计决策没有落到 Token 上。

**改法**：按角色定 5 个值——媒体 2、容器 8、卡片 12、弹层 28、胶囊 Full。删掉 1/4/5/6/7/9/10/14/16/20/24 的裸写。

#### S-02 顶栏

| 页面 | 高度 | 实现 |
| --- | --- | --- |
| 相册/时间轴/Pixiv/清理 | 60dp | `VaultTopBar` / `CleanupToolbar` |
| 编辑器 | 64dp | 自绘 `EditorTopBar` |
| 查看器 | 68dp | 自绘 `ViewerTopBar` |
| 设置子页 | 44dp | `SettingsSectionHeader` |
| 工具箱 | 60dp | 自绘标题行 |
| 选择模式副栏 | 36dp | `SelectionSubBar` |

同一个"页面顶部"，有 44/60/64/68dp 四档高度、五种实现（含工具箱自绘）。用户在页面间切换时，标题的垂直位置会跳。

**改法**：标准页 56dp（含状态栏内边距另算），沉浸式查看器/编辑器 56dp，选择模式 56dp；删除 36dp 副栏（见 5.2）。

#### S-03 栅格与间距

- 页边距：相册/时间轴/清理/壁纸都是 **7dp**；
- 相册网格间距：**15dp**；时间轴：**3dp**；壁纸：**4/6dp**；幻灯片：**4/6dp**；
- 设置卡片内边距：14/16dp；行高 66dp；清理入口 82dp；
- 底部：底栏 68dp，查看器 76dp。

`7dp` 不在 4dp 基准上，`3dp` 也不在。结果是在 360dp 宽的手机上，3 列封面每列约 105dp、间距 15dp，视觉重心偏"松"；时间轴 4 列 3dp 又偏"挤"。两者都没有错，但**不是同一套节奏**。

**改法**：页边 12dp；网格间距 4dp；列表行高 64dp；卡片内边距 16dp；区块间距 24dp。见 [8.4](#84-间距与栅格)。

#### S-04 同一张图，三种圆角

- 时间轴/文件夹内页：**0dp（直角）**；
- 相册根页封面：**8dp**；
- 壁纸队列：**4dp**。

用户会感觉"时间轴更硬、相册更软"，但这是无意的。**改法**：媒体统一 2dp（印样感），容器/卡片统一 8–12dp；按"媒体 vs 容器"分，而不是按页面分。

### 3.4 表面与层级：白上白，黑上黑

#### L-01 卡片没有边界

见 C-06。补充一点：设置页的分类卡还用强调色做 chevron 和图标底，而值行用 `onSurfaceVariant`，视觉上"图标比标题更响"，层级倒了。

#### L-02 阴影只在清理页出现

清理页选中的 Tab 有 `shadow(2.dp)`（[`CleanupScreen.kt`](../app/src/main/java/com/example/album/ui/screens/CleanupScreen.kt#L733-L740)），底栏拖拽幽灵 6dp，菜单默认阴影，其余全平。阴影不是不能用，但"只有清理页的 Tab 有"会让它看起来像另一个 App 的控件。

**改法**：阴影只用于"临时浮起"（拖拽幽灵、菜单、Snackbar），静态卡片一律用细线。

#### L-03 视频上的菜单是 20% 黑

查看器的视频菜单容器用 `Color.Black.copy(alpha = .20f)`（[`MediaViewer.kt`](../app/src/main/java/com/example/album/ui/components/MediaViewer.kt#L930-L933)）。在明亮画面上，白字菜单几乎糊在视频里；同时菜单只裁了左侧 14dp 圆角（`clip(RoundedCornerShape(topStart=14, bottomStart=14))`），右侧是直角，和内容对不齐。

**改法**：菜单用不透明 `surface` + 细线 + 3dp 阴影；圆角四角一致 16dp；离屏幕边缘 8dp。

### 3.5 图标与品牌：一个 P 标记的三种用法，一个多余的绿

#### B-01 图标风格与尺寸

- 主体是 Material Outlined 默认集（Collections、WatchLater、Widgets、Settings）；
- 底栏 Pixiv 用自绘 `PixivPMark`，外面套一个 **24×24 纯白方块**，在深色底栏上就是一块白斑（[`AppBottomBar.kt`](../app/src/main/java/com/example/album/ui/AppBottomBar.kt#L253-L267)）；
- 另有文字 "p" 作为 fallback（`PixivP` 在部分位置被当作字形）；
- 图标尺寸散落 16/17/19/20/21/22/23/24/25dp 九种。

**改法**：默认 24dp、行内 20dp、密集元数据 16dp；只保留 Outlined 一套，**填充只表示"已选中/已激活"**；Pixiv 标记用品牌方块（不套白底），深色主题用 12% 白的衬底或直接透明。

#### B-02 启动图标有第三种绿

`ic_launcher_foreground.xml` 是蓝底 + 白照片 + 柠檬绿 `#A8F27A` 的太阳。柠檬绿不在 7 个主题色里，也不在语义色里。启动图标与 App 内配色没有关系。

**改法**：图标只用"蓝 + 白 + 一个暖色点"，暖色点取金色 `#FAD000`（安全灯），与主题色板同源；monochrome 变体已存在，保留。

#### B-03 深色模式没有 night 资源，启动会白闪

`Theme.Albumiv` 的父主题是 `android:Theme.Material.Light.NoActionBar`（[`themes.xml`](../app/src/main/res/values/themes.xml#L1-L5)），且没有 `values-night/`。这意味着：

- 深色模式下，启动窗口仍是浅色 → **白闪**；
- `enableEdgeToEdge()` 默认按系统配置判断明暗（[`MainActivity.kt`](../app/src/main/java/com/example/album/MainActivity.kt#L95)），而 App 的深色是应用内强制的 → 系统栏图标很可能仍是深色，落在深色背景上不可见；
- 只有编辑器显式改了 `isAppearanceLightStatusBars`（[`ImageEditorDialog.kt`](../app/src/main/java/com/example/album/ui/editor/ImageEditorDialog.kt#L353)），主界面没有。

这条标注为 **高概率问题，需真机复现**：系统浅色 + App 内选"深色" → 看状态栏时间/电量是否可见；冷启动 → 看是否先白后黑。

**改法**：`values-night/themes.xml` 提供深色启动背景；在 Compose 根用 `SideEffect` 按 `darkTheme` 设置 `isAppearanceLightStatusBars` / `isAppearanceLightNavigationBars`；API 31+ 配 `windowSplashScreenBackground`。

### 3.7 反馈与文案：81 个 Toast，0 个可撤销

#### F-01 结果只能靠 Toast

全仓库 **81 处 `Toast.makeText`，0 处 Snackbar**。Toast 的特点正好是产品最不需要的：2 秒消失、不能带动作、不能撤销、在底部遮挡内容、对屏幕阅读器不友好（部分 ROM 不播报）。

典型："已加入幻灯片队列""已复制 Pixiv 网址""已彻底删除 12 项"——这些都应该是一个带"撤销"的 Snackbar，或就地状态变化。

#### F-02 没有撤销，只有确认

有约 **34 处确认/提示弹层**，说明团队很怕误操作；但"事前确认"不能替代"事后撤销"。用户点"删除"后弹窗、再点"删除"，两次确认之后仍然没有后悔药（回收站是好的，但只覆盖删除）。

**改法**：三级危险操作（见 5.5）：可逆的（移出队列、收藏、重命名）直接做 + Snackbar 撤销；进回收站的删除直接做 + 撤销；永久删除才用确认弹层。

#### F-03 按钮文案与位置不统一

`VaultDialogLabels` 已经把"取消/完成/知道了/应用/关闭"收口（[`VaultDialogs.kt`](../app/src/main/java/com/example/album/ui/components/VaultDialogs.kt#L564-L574)），这是好实践。但英文映射把"完成"和"知道了"都翻成 `Done`，在同一个弹层体系里意味着两件事。

中文里还混入英文："查看/编辑 Tags"。对普通用户，"Tags" 不如"标签"；对 Pixiv 用户，"Tag" 是行业词。建议首次出现写"标签（Tag）"，之后统一"标签"。

#### F-04 数字没有量词，四种格式

- 时间轴顶部：`50303`（裸数字，右对齐，无单位，见 [`TimelineScreen.kt`](../app/src/main/java/com/example/album/ui/screens/TimelineScreen.kt#L397-L404)）；
- 相册封面：`80`（10sp，右对齐）；
- 幻灯片：`12 项`（左对齐）；
- 壁纸文件夹：`4 个文件夹`（右对齐）；
- 清理：`12 组重复图片`（17sp 摘要）。

同一个"数量"，位置、字号、量词、对齐方式全不同。**数字必须带单位，并且只有一种排版。**

#### F-05 本地化是"手写字典 + 静默回退"

[`appText()`](../app/src/main/java/com/example/album/ui/AppLanguage.kt#L8) 的逻辑是 `APP_ENGLISH[chinese] ?: chinese`：英文缺失时**显示中文，不报错、不告警**。再叠加大量 `if (english) "..." else "..."` 内联字符串，词典覆盖率无法保证。

更具体的问题：

- [`MediaTiles.kt`](../app/src/main/java/com/example/album/ui/components/MediaTiles.kt#L204-L215) 的 `stateDescription` 硬编码"已选中/未选中"，英文界面下 TalkBack 会中英混读；
- 英文文案大小写不统一：`"View/Edit Tags"`、`"Long-press..."`、`"No photos yet"` 混用；
- 日期格式已正确处理（`Today · Nov 24`），这是好的，应作为其他文案的标杆。

**改法**：新增 `MissingTranslationTest`（遍历所有 `appText` 调用点，英文缺失即失败）；把高频 `if (english)` 迁入词典；语义描述统一走 `appText`；英文统一 Sentence case。

## 4. 逐屏处方

> 每屏只列"必须改"的，不重复第 3 章已解释的原理。尺寸均为 dp，颜色引用第 8 章 Token。

### 4.1 相册根页

**现状**：顶部是"图片/视频"滑块 + 搜索 + 星标 + 溢出；3 列文件夹；名称 13sp、数量 10sp；底栏只有选中项有文字。

**处方**：

1. **恢复页面标题**。顶栏 56dp：`相册` 20/26 SemiBold + 搜索/溢出各 48dp。
2. **筛选行 44dp**：左"图片/视频"分段（40dp 高，容器 8dp 圆角），右"12,304 张"（11/14，tabular）。星标从顶栏移到筛选行，做成"收藏"筛选 chip（星形 + 文字），不再是一个孤立的星。
3. **文件夹卡**：封面 4dp 圆角；名称 13/18 一行；数量改为**第二行**"80 张"，11/14 muted，带量词。这样名称不再被数量挤到截断（当前"墨羽 [709129…"）。
4. **长名称**：允许 2 行，行高 18；或在长按预览/选择态显示全名。Pixiv 画师名 + ID 是常态，必须有解。
5. **排序/布局**：不要全塞进溢出。筛选行右侧加一个"排序"chip；布局/列数留在溢出。
6. **底栏**：5 个标签全部显示，11/14；选中 = 实心图标 + 强调色 + 2dp 下划线；未选中 = 线性图标 + 60% 墨色。

```
┌──────────────────────────────────┐
│ 相册                        ⌕  ⋮ │ 56
```

### 4.2 时间轴

**现状**：顶部裸数字 `50303` 占一整行；日期头不吸顶；4 列 3dp 直角；跳日期藏在溢出菜单；滚动条是自定义细条。

6. **滚动条**：保留自定义细条，但宽度 5dp、距边 2dp、只在滚动时出现；`persistent` 设置保留。

**验收**：5 万张列表从顶部拖到 2019 年不超过 2 次操作；滚动时日期始终可见；首行不再出现裸数字。

### 4.3 Pixiv

**现状**：唯一有页面大标题的页；蓝色横幅"Pixiv 文件归档"；3 列网格与相册一致；搜索时的"画师/Tag"模式是一个 11sp 文字 + 交换图标的循环切换。

**处方**：

### 4.4 查看器

**现状**：顶栏 68dp，返回 + 文件名/位置（14sp，居中于剩余空间）+ 星标 + 信息 + 溢出；底栏 76dp，5 个纯图标动作；菜单里"信息"重复出现；视频菜单 20% 黑。

**处方**：

1. **顶栏 56dp**：返回 48 + 标题区（文件名 15/20 Medium，下一行"12 / 340"11/14 muted）+ 星标/溢出。**真正的居中**需要左右两侧等宽（各 96dp 或 48dp 占位），当前标题是在剩余宽度里居中，视觉偏左。

5. **菜单**：不透明 surface、16dp 四角、8dp 边距、3dp 阴影；分组用分隔线，不用 20% 黑。

**验收**：在 360dp 宽下，文件名 + 位置 + 3 个动作不重叠；删除/移动/复制不看图标也能区分。

### 4.5 编辑器

**验收**：所有可点元素 ≥48dp；1.5 倍字体下"完成/分辨率"不换行；撤销 10 次不丢状态。

**现状**：顶栏只有返回 + 3 个文字 Tab（48dp 分段）；没有页面标题；"扫描/清理全部"是 9sp 的文字；空态一行灰字；重复组用 17sp 摘要。

**现状**：分类卡 + 13 个分区；卡片 `surfaceVariant` 1.02:1；分区标题 11sp；行值用强调色；自定义开关 48dp 画布；子页头 44dp；主题色叫"Pixiv 蓝"。

## 5. 交互语法统一

### 5.1 导航与返回

**底栏**：5 个 Tab，全部显示图标 + 文字；选中态 = 实心图标 + 强调色 + 2dp 下划线；未选中 = 线性图标 + 60% 墨色。不要只给选中项显示文字。

| 场景 | 当前 | 建议 | 理由 |
| --- | --- | --- | --- |
| 页面身份 | 相册/时间轴用开关代替标题 | 标题 + 筛选行 | 用户需要知道"我在哪" |
| 再点当前 Tab | 回顶，再点刷新 | 只回顶；刷新用下拉 | 导航不应触发扫描 |
| 返回 | 各页自绘箭头 | 系统返回 + 预测性返回（需 opt-in） | Android 惯性 |
| 文件夹 | 返回根页 | 保留；标题显示文件夹名 | 已有，补标题即可 |
| 查看器 | 返回网格 | 保留；返回时恢复滚动位置 | 已有 |
| 选择模式 | 返回退出选择 | 保留；先退选择再退页面 | 符合层级 |

**返回优先级**：弹层 > 查看器 > 选择模式 > 文件夹 > 根 Tab > 退出 App。用 `BackHandler` 统一实现，避免各页各写一套。

### 5.2 选择模式：只留一套操作面

当前多选时屏幕上下各有一排操作，功能重叠。**Android 的行业做法是"上下文操作栏"：进入选择后，顶栏变成选择栏，底栏导航被操作栏替换。**

```
┌──────────────────────────────────┐
│ ×   已选 3 / 120        全选   ⋮ │ 56
├──────────────────────────────────┤
│  [缩略图] [缩略图] [缩略图] ...    │
│                                  │
├──────────────────────────────────┤
│  删除     移动     复制     更多   │ 56
└──────────────────────────────────┘
```

规则：

- 长按进入选择；单击切换选中；长按后继续拖动 = 范围选择（保留现有手势）。
- 计数"已选 3 / 120"是 live region，选择变化时播报。
- "全选"是文字按钮，不是 16dp 圆圈；触控 48。
- 底栏 4 个主动作：删除（danger，带文字）、移动、复制、更多（重命名/分享/收藏/信息/编辑标签）。
- 顶栏不再放删除/移动/重命名/收藏，避免两套。
- 退出选择：左上 ×，或系统返回。
- 选择态下点击媒体 = 切换选择，不再打开查看器；这是 Google Photos 的惯性。

### 5.3 手势：加速器，不是唯一入口

| 手势 | 位置 | 当前 | 建议 | 可见入口 |
| --- | --- | --- | --- | --- |
| 长按 | 网格 | 进入多选 | 保留 | 溢出菜单"选择" |
| 长按拖动 | 网格 | 范围选择 | 保留 | 同上 |
| 单击 | 查看器 | 显隐 chrome | 保留 | 无（行业默认） |
| 双指 | 查看器 | 缩放 | 保留 | 无（行业默认） |
| 左右滑 | 查看器 | 切换图片 | 保留 | 底部位置"12/340" |
| 上下滑（左/右半屏） | 视频 | 亮度/音量 | 保留，但首次给 3s 提示 | 播放器菜单"手势说明" |
| 双击左/右 | 视频 | ±10s | 保留，加视觉反馈 | 同上 |
| 长按底栏 | 底栏 | 拖动排序 | 保留，但加"拖动排序"首次提示；默认关闭 | 设置开关 |
| 下拉 | 列表 | 刷新 | 保留 | 无（行业默认） |
| 再点 Tab | 底栏 | 刷新 | 删除刷新，只回顶 | 无 |

**原则**：任何一个手势，如果不能在界面上找到等价按钮，就必须在首次使用时给一次可跳过的提示；提示不能是唯一的入口。

### 5.4 控件语汇

只允许这六类控件。新页面只能从这六类里选，不能自创。

| 类型 | 用途 | 规格 | 状态 |
| --- | --- | --- | --- |
| **Button / Primary** | 一屏一个主行动 | 52dp 高，Full 圆角，实心 accent，15/20 SemiBold | default / pressed(8%) / disabled(38%) / loading |
| **Button / Secondary** | 次行动、取消 | 48dp 文字按钮，15/20，onSurface | default / pressed(8%) |
| **Segmented** | 2–3 个互斥视图切换 | 40dp 高，容器 8dp，thumb 6dp，12/16 Medium | selected = 白底 + 1px 线 + 强调色文字 |
| **Chip / Filter** | 可开关的筛选 | 视觉 32dp，触控 48dp；Full，12/16 | off = 1px line；on = 12% accent + accent.text |
| **Row** | 设置/列表项 | 64dp 高，16dp 内边距，标题 15/20 + 说明 12/16 | pressed 6% tint |
| **IconButton** | 只放图标 | 视觉 24，触控 48（`minimumInteractiveComponentSize`） | default / disabled(38%) |

**禁止**：32dp 高的可点胶囊、9sp 文字按钮、2dp 描边胶囊主按钮、只有图标没有语义的"全选"。

### 5.5 危险操作分三级

| 级别 | 例子 | 交互 | 恢复 |
| --- | --- | --- | --- |
| 1 可逆 | 收藏、加入/移出队列、重命名 | 直接执行 + Snackbar | "撤销" 5s |
| 2 进回收站 | 删除图片/视频 | 直接执行 + Snackbar | "撤销" 5s；回收站 30 天 |
| 3 不可逆 | 彻底删除、清空回收站 | 确认 sheet，写清数量与后果，按钮"永久删除 12 项" | 无 |

原则：**能用撤销解决的，不要用确认弹层。** 确认弹层只留给不可逆操作；否则用户会练成"无脑点确定"。

### 5.6 反馈矩阵

| 结果类型 | 通道 | 时长 | 动作 |
| --- | --- | --- | --- |
| 成功且可逆 | Snackbar | 5s | 撤销 |
| 成功且不可逆 | Snackbar | 3s | 无 |
| 失败可重试 | Snackbar / 就地 banner | 5s | 重试 |
| 失败需解释 | 就地 banner（持久） | 直到关闭 | 重试 / 详情 |
| 进行中 >1s | 就地进度（行内/顶部线） | 直到完成 | 取消（可取消时） |
| 权限/引导 | 空态或一次性 coach mark | 直到操作 | 主按钮 |

**废弃**：所有"操作结果"类 Toast。保留 Toast 仅用于系统级、无 UI 上下文的失败（如"没有可打开此文件的应用"），并尽量改为 Snackbar。

### 5.7 空态、加载、错误三态

见 4.9。统一为一个 `VaultEmptyState` 组件和 `VaultBanner` 组件；每个列表页必须实现三态，不能只实现"有数据"。

### 5.8 文案与本地化规则

1. **动词开头，具体对象**：主按钮"删除 12 项"而不是"确定"。
2. **中文量词**：张（图片）、个（视频/文件夹）、项（队列）、组（重复）、条（提示）。
3. **英文 Sentence case**：`Delete 12 items`，不是 `Delete 12 Items`。
4. **一词一义**：`完成`=提交（编辑保存），`知道了`=关闭说明，`取消`=放弃，`应用`=使设置生效；英文分别 `Done / Got it / Cancel / Apply`，不要都用 `Done`。
5. **Tags**：中文"标签（Tag）"首次出现后统一"标签"；英文统一 `Tags`。
6. **日期**：沿用现有 `今天 · 11月24日` / `Today · Nov 24`，跨年补年份。
7. **数字**：一律带单位/量词，使用 tabular numerals；不要裸数字。
8. **不静默回退**：英文缺失时开发期报错（测试失败），而不是显示中文。

## 6. 动效：从"会动"到"有因果"

### 6.1 现状

- 动画几乎全部由 `tween` 驱动（63 处），**0 处 `spring`**；
- 16 种时长：85/90/100/120/140/160/170/180/190/200/220/240/260/300/360/900ms；
- 4 条贝塞尔曲线，其中 3 条几乎一样（`.22,.8,.28,1`、`.22,1,.36,1`、`.22,.78,.24,1`）；
- 同一次 Tab 切换，顶部栏用 190/240ms，内容页用 380ms + 18ms 延迟（[`AlbumivApp.kt`](../app/src/main/java/com/example/album/ui/AlbumivApp.kt#L3057-L3073) 与 [`AlbumivApp.kt`](../app/src/main/java/com/example/album/ui/AlbumivApp.kt#L3453-L3470)）——**头和身体不同步**；
- 按压反馈：网格缩放 0.965–0.975，设置行 6% tint，底栏/编辑器 Tab 无（`indication = null` 且全局 ripple 被关，[`Theme.kt`](../app/src/main/java/com/example/album/ui/theme/Theme.kt#L65)）。

### 6.2 四条动效原则

1. **因果**：动效必须解释"从哪来、到哪去"。共享元素、面板从底部升起、选择栏从顶部展开，都是因果；无意义的淡入不是。
2. **层级**：一次状态变化只允许一个主运动（位置），其他属性（颜色/透明度）跟随，不能三个属性各用一套时长。
3. **可中断**：拖拽、滑动必须跟手（spring 或直接 set），不能在手指离开后才播放动画。
4. **克制**：装饰性动画默认关闭；循环动画（骨架、GIF）必须尊重"减少动态"。

### 6.3 Token

```kotlin
object VaultMotion {
    const val Instant = 100      // 按压、状态 tint
    const val Quick = 160        // 开关、chip、选择栏
    const val Standard = 220     // 页面、面板、菜单
    const val Emphasized = 320   // 共享元素、弹层
    const val Ambient = 1200     // 仅骨架呼吸/装饰

    val StandardEasing = CubicBezierEasing(0.2f, 0f, 0f, 1f)   // M3 emphasized
    val Decelerate = CubicBezierEasing(0.05f, 0.7f, 0.1f, 1f)
    val Accelerate = CubicBezierEasing(0.3f, 0f, 0.8f, 0.15f)

    fun <T> spatial() = spring<T>(dampingRatio = 0.9f, stiffness = 380f)
}
```

规则：

- **位置/尺寸**：`spring`（拖拽幽灵、底栏滑块、选择栏高度）。
- **透明度/颜色**：`tween`（`Instant`/`Quick`）。
- **页面/弹层**：`tween(Standard/Emphasized, StandardEasing)`。
- 一个元素最多同时动画 2 个属性；超过就拆成父子层。

### 6.4 关键转场清单

| 场景 | 运动 | 时长/曲线 | 备注 |
| --- | --- | --- | --- |
| Tab 切换 | 内容淡入 + 8% 横向位移；顶栏同步 | 220ms / Standard | 顶栏与内容同一时长、同一曲线；删除 380ms 的另一套 |
| 进入文件夹 | 共享元素封面 + 内容淡入 | 320ms / Emphasized | 保留现有共享元素 |
| 打开查看器 | 图片从缩略图位置放大 | 320ms / Emphasized | 背景 220ms 变黑 |
| 退出查看器 | 反向 | 220ms / Decelerate | 可中断 |
| 进入选择 | 顶栏切换为选择栏；内容让出底栏 | 160ms / Quick | 不要从 36dp 副栏再长出来 |
| 弹层 | 从底部升起 + 遮罩淡入 | 内容 320ms / 遮罩 220ms | 支持手势下拉关闭 |
| 编辑器面板 | 底部面板高度变化 | 220ms / Standard | 画布不缩放，只让出空间 |
| 底栏排序 | 幽灵跟手，槽位 spring | spring | 松手后 160ms 归位 |
| 删除/撤销 | Snackbar 从底栏上方升起 | 160ms | 不与底栏重叠 |

### 6.5 减少动态

- Compose 的 `MotionDurationScale` 已自动遵循系统"动画时长缩放"；不要在业务代码里直接读 `Settings.Global`（无谓权限与兼容风险）。
- App 内设置"减少动态"：关闭骨架呼吸、GIF 缩略图自动播放、壁纸预览轮播；页面转场改为淡入 120ms；共享元素改为淡入。
- 无限动画清单：骨架呼吸、下拉刷新旋转、GIF 缩略图、壁纸预览。全部要能停。

### 6.6 性能边界

- 共享元素 + 全屏模糊/大阴影是掉帧高风险；保持现有"只动 transform/alpha"的做法，不动 `blur`、不动 `shadowElevation`。
- 网格滚动时不要触发每项的 `animateColorAsState`；选择态颜色用 `snap` 或父级统一绘制。
- 60fps 目标下，4 列网格单帧不超过 2 次布局；骨架屏不要每帧重建。

| `VaultSwitch` | 标准 52×32、边框、语义 | 自绘、关闭态不可见 |
| `VaultCount` | 数字 + 量词 + tabular | 无 |

先把这 12 个组件做完，新页面就只能"拼"，不会再长出第 5 套 Tab。

### 8.7 治理

- **Owner**：指定一人对 `ui/theme/` 与 12 个组件有合并权；其他页面只能提需求，不能加字面量。
- **PR 检查**：CI 加 `grep` 规则——`ui/screens/` 出现 `fontSize =`、`Color(0x`、`RoundedCornerShape(` 直接失败（白名单除外）。
- **截图回归**：每次改 token 生成 light/dark × 3 强调色基线。
- **文档**：一页 `docs/design-system.md`，只放 token 表 + 组件 do/don't；本文作为"为什么"的背景。

## 10. 保护清单：这些不要改

1. **网格优先**：不要为了"设计感"给缩略图加大圆角、阴影、白边。
2. **按压缩放**：0.965/0.975 的手感是全 App 最好的细节，保留并扩展到所有可点卡片。
3. **共享元素**：图片进查看器的飞行是品牌时刻，保留；只调时长到 320ms。
4. **纯黑查看器**：OLED 省电且让图像最准，保留。
5. **7 套强调色**：用户有选择权是好事；只修色阶，不删颜色。
6. **手势提示**：保留，但改成"首次触发时的一次性提示 + 设置里的完整列表"。
7. **本地优先**：任何视觉改动不得引入云端依赖、分析 SDK 或网络字体。
8. **高密度信息**：设置里的说明文字是优点，不要为了"简洁"删掉；用分层和折叠解决长度。

### 最后一段

这份稿子的重点不是"改成什么样"，而是**建立一套让下一屏自动正确的机制**。Albumiv 的功能密度和本地优先的坚持已经很难得；它现在缺的不是更多功能，而是一次收口：把四种"切换"变成一种，把十七级字号变成六级，把 81 个 Toast 变成一套可撤销的反馈，把"藏在提示里的手势"变成"看得见的入口"。

这些事情不需要重写 App，只需要一个 owner、一张 Token 表、十二个组件，和两周的克制。
